- [ ] 安南與叡揚合約中的保密、資料返還及其他限制條款，列入律師審閱
- [ ] 安南「以什麼系統取代叡揚」的相關決策，本人迴避
- [ ] 競品展示以醫點名義、公開身分索取，不使用安南採購評估的管道
- [ ] 內部文件中對廠商的描述，以「使用情境與需求缺口」呈現，不做產品評價；市場分析標註為內部文件，不對外分享

## 合作模式
- [ ] 與資訊公司合作：對方投標、導入、維運；醫點收授權費或分潤
- [ ] 合約要點：授權範圍、分潤計算、維運責任、資料處理者義務、終止後資料返還
- [ ] 原始碼託管（escrow）：合約要求時再設
- [ ] 部署文件從第一天就維護（見 [deployment.md](../06-deployment/deployment.md)）

## 著作權（標準條文）
- [ ] ISO 條文：系統只存結構（編號、標題），`text_policy = structure_only`，資料庫 trigger 強制
- [ ] 評鑑基準：確認發布機關的授權條件後決定 `summary` 或 `full`；確認前一律 `summary`
- [ ] JCI 標準：同 ISO，預設 `structure_only`

## 資安與隱私
- [ ] 預設地端部署，文件與模型推論不出院
- [ ] 程式碼稽核可委外
- [ ] 關鍵資安稽核（滲透測試、架構審查）另找獨立廠商
- [ ] 個資盤點：會議紀錄可能含病人個案討論 → 需界定處理範圍與遮蔽策略
- [ ] 留存期限與刪除機制（`retention_months`、稽核軌跡 `audit_log`）
- [ ] 醫點月費代管模型：院內資料出院前必須去識別化，並在合約中明定資料處理範圍（ADR-0005）
- [ ] 導入分析 Agent 掃描院內檔案：唯讀、在院內執行、取得書面授權（ADR-0014）
- [ ] 舊 KM 合約到期前，完成含描述資料的資料匯出（見專案計畫的風險 #1）

## 範圍守則
