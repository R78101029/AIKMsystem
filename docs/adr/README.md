# 架構決策紀錄（ADR）

每個重要決策一節；被推翻時新增一節並標註取代關係，不刪除舊紀錄。

## ADR-0001 檔案不搬家，系統是覆蓋層
- **狀態**：已採納（2026-11-02）
- **決策**：實體檔案留在院方既有儲存（O365 等），系統只存參照、metadata 與抽出文字。Metadata 以系統資料庫為準。
- **理由**：降低導入阻力與資料遷移風險；院方換儲存平台時只需換轉接器。
- **代價**：需處理外部檔案被移動／刪除（以 `etag`、`content_sha256` 偵測），需要同步機制。

## ADR-0002 「評鑑基準」泛化為「標準框架」
- **狀態**：已採納（2026-11-02）
- **決策**：資料模型以 `framework → framework_version → requirement` 表達，不寫死醫院評鑑；跨框架以 `crosswalk` 對應。
- **理由**：可擴充 ISO 9001／15189／27001、JCI、疾病照護品質認證；跨框架對應是產品賣點。範圍限醫療機構。

## ADR-0003 標準條文著作權以資料庫層強制
- **狀態**：已採納（2026-11-02）
- **決策**：`framework.text_policy` 分 `full`／`summary`／`structure_only`，由 trigger 拒絕在非 `full` 框架存原文。
- **理由**：靠應用程式自律不可靠；資料庫層強制，任何匯入工具都無法誤存。

## ADR-0004 向量固定 1024 維、存於 Postgres（pgvector）
- **狀態**：暫定（2026-11-02）
- **決策**：`chunk.embedding vector(1024)` + HNSW cosine 索引；記錄 `embedding_model`。
- **理由**：單一資料庫降低維運負擔；1024 維涵蓋多數地端多語 embedding 模型。
- **後續**：若換用不同維度模型，以新 migration 新增欄位並重建，舊欄位保留至切換完成。

## ADR-0005 AI 產出一律「建議 → 人審」，並全程留痕
- **狀態**：已採納（2026-11-02）
- **決策**：AI 產出起始狀態為 `suggested`／`pending`，必附 citation；每次呼叫記 `ai_run`；人審結果可升級為黃金測試集。
- **理由**：評鑑佐證需可追溯；模型可抽換的前提是有回歸測試。
