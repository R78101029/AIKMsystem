# 03 · MVP-0 範圍（約 1.5 人月，自己做）

## 目標
用**一類**最痛的 D／C 證據，跑通一條完整路徑：

> 紀錄進來 → AI 歸類 → 逐要素完整性檢查（附出處）→ 人審 → 燈號 → 一鍵佐證清單
> ＋ 規章與紀錄一致性比對（Find → Explain → Grade）

證明「證據規格」這個抽象可行，並產生第一批黃金測試集。

## 候選證據類別比較

| 候選 | 痛度 | 規律性（可算逾期） | 要素可檢查性 | 規章對照（一致性） | 跨框架價值 | 取得難度 |
|---|---|---|---|---|---|---|
| **委員會會議紀錄**（感管、病安、品管、藥事…） | 高：數量多、評鑑必翻 | 高：多為每季／每月 | 高：日期、主席、出席率、前次決議追蹤、決議負責人與期限 | 高：設置辦法明定開會頻率、主席、委員組成 | 高：評鑑、ISO 管理審查、JCI 皆要求 | 低：文書檔為主 |
| 教育訓練紀錄 | 高 | 中：年度時數 | 中：需對照人員名冊 | 中 | 中 | 中：多在其他系統 |
| 設備保養／檢查紀錄 | 中 | 高 | 中：表單勾選為主 | 中 | 中（ISO 15189 高） | 中：多為紙本掃描 |
| 品質指標監測報告 | 高 | 高 | 低：判斷「有沒有檢討」較主觀 | 中 | 高 | 中 |

## 建議：委員會會議紀錄

理由：
1. **要素結構化程度最高**，AI 完整性檢查容易驗證對錯，最適合建立第一批黃金測試集。
2. **天然有 P 對 D 的一致性題目**：設置辦法說「每季開會、院長主持、委員含 X」，紀錄是否做到——正好示範 Find → Explain → Grade。
3. **PDCA 閉環內建**：「前次決議追蹤」本身就是 C→A 的證據。
4. **跨框架展示**：同一份紀錄同時對應評鑑條款與 ISO 9001 管理審查，示範賣點。
5. 文件多為 Word／PDF 文字檔，OCR 風險低。

建議先鎖定 **2–3 個委員會**（例：感染管制、病人安全、醫療品質），各取近 2 年紀錄。

## MVP-0 功能清單

- [ ] 標準框架匯入：一個框架（評鑑相關章節）只存結構＋自撰摘要
- [ ] 證據規格編輯：委員會會議紀錄 × 2–3 個委員會，含必備要素
- [ ] 證據入口：網頁上傳（基本款）；專用收件信箱可延到 MVP-1
- [ ] 文件解析：DOCX／PDF → 切塊 → embedding
- [ ] AI 歸類：判斷是哪個委員會、哪一期
- [ ] AI 完整性檢查：逐要素 present/partial/absent＋引文
- [ ] AI 一致性比對：設置辦法 vs 會議紀錄（頻率、主席、組成）
- [ ] 人審佇列：接受／修改／拒絕，可標記入黃金測試集
- [ ] 燈號儀表板＋一鍵佐證清單（依條款列出已確認紀錄）
- [ ] 黃金測試集評測腳本（至少 30 個案例）

## 不做（MVP-0）
- M365／Google／NAS 同步、LINE／Teams 通知
- 多租戶、RLS、細緻權限
- 變更影響模組（資料表已備，邏輯延後）
- 美觀的前端

## 驗收標準（建議）
- 歸類正確率 ≥ 90%（以黃金測試集計）
- 要素判斷與人審一致率 ≥ 85%，且每個判斷都有可點回原文的引文
- 從上傳到燈號更新 < 2 分鐘（地端模型）
- 示範：準備評鑑某條時，一鍵產出該條佐證清單

## 資料取得注意
MVP-0 若使用安南實際文件，須先完成利益揭露與院方書面同意（見 [04-business-compliance.md](04-business-compliance.md)），並以去識別化資料建立黃金測試集；在同意前，用自製模擬文件開發。
