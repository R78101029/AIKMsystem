## 1. 六層架構

```
┌──────────────────────────────────────────────────────────────────┐
│ ① 使用介面    任務視角 · 單位視角 · 條款視角 · 審核佇列 · 燈號／準備度  │
├──────────────────────────────────────────────────────────────────┤
│ ② Agent 編排層  導入分析 Agent · 稽核監控 Agent                     │
│                 （只能呼叫③；只產出建議與通知）                      │
├──────────────────────────────────────────────────────────────────┤
│ ③ 應用模組    收件與任務 · 歸類 · 要素檢查 · 一致性稽核 · 對應與缺口  │
│               · 文件管制 · 簽核 · 變更影響 · PDCA · 燈號與佐證       │
├──────────────────────────────────────────────────────────────────┤
│ ④ AI 服務層   任務介面 · 模型路由 · 提示詞版本 · 呼叫紀錄 · 黃金測試集│
├──────────────────────────────────────────────────────────────────┤
│ ⑤ 知識核心    組織／成員關係 · 框架→版本→條款 · 證據規格 · 文件／版本 │
│               · 證據 · 設定繼承 · 領域套件 · 稽核軌跡（Postgres）     │
├──────────────────────────────────────────────────────────────────┤
│ ⑥ 轉接器      儲存 · 副本存放 · 收件 · 通知 · 模型 · 登入 ·（簽章）   │
└──────────────────────────────────────────────────────────────────┘
```

**呼叫方向只能由上往下，不可以跨層直接存取別層的內部。**
- Agent 不可以直接改資料庫，也不可以直接呼叫模型。
- 應用模組之間只透過公開介面互相呼叫。

## 2. 核心原則

| 原則 | ADR |
|---|---|
| 以條款為錨點；證據規格是翻譯層；提供三種視角 | [0001](../adr/0001-requirement-as-anchor.md) |
| 框架泛化；證據規格與條款多對多 | [0002](../adr/0002-framework-generalization.md) |
| 原檔不搬家；確認的證據另存不可修改的副本 | [0004](../adr/0004-overlay-and-immutable-archive.md) |
| 只呼叫 AI 任務，不直接呼叫模型；模型可以依院區 × 任務路由 | [0005](../adr/0005-ai-task-interface.md) |
| AI 產出「建議 → 人審」，附出處、全程留痕 | [0006](../adr/0006-ai-suggest-human-review.md) |
| 核心不分產業，產業差異放在領域套件 | [0013](../adr/0013-industry-neutral-domain-packs.md) |
| 以流程強制關聯，不靠使用者自律 | [0015](../adr/0015-workflow-enforced-linkage.md) |
| 地端優先：文件與含個資的推論預設不出院 | [0005](../adr/0005-ai-task-interface.md) |

## 3. 彈性機制

| 變動方向 | 機制 |
|---|---|
| 多評鑑、多認證 | 資料驅動：框架以範本匯入，不寫在程式裡 |
| 多院、多院區、多單位 | 組織樹加成員關係；設定分層繼承（系統 → 租戶 → 院區 → 單位） |
| 多模型來源 | 模型轉接器加路由表；資料政策 |
| 多儲存 | 儲存轉接器、副本存放轉接器 |
| 多帳號系統 | 登入轉接器 |
| 多產業 | 領域套件 |
| 機構特殊流程 | 生效流程、簽核流程可以設定（例：委員會通過 → 公文核准才生效） |

各轉接器要**宣告自己的能力**（例如是否支援增量同步、版本紀錄、寫入後鎖定），核心依宣告的能力調整做法；做不到的功能改用替代做法，不會因此出錯。

## 4. 轉接器一覽

| 轉接器 | 介面要點 | MVP-0 | MVP-1 | 產品版 |
|---|---|---|---|---|
| 儲存 | 列出異動、讀檔、查詢狀態 | 內建 | O365（Sites.Selected、增量同步） | Google、NAS |
| 副本存放 | 寫入（不可修改）、讀取、驗證雜湊 | 本機磁碟 | S3 相容（寫入後鎖定）、NAS | — |
| 收件 | 拉取收件項目 | 網頁上傳 | 專用信箱、O365 資料夾、舊 KM 匯入 | — |
| 通知 | 發送 | — | Email | LINE、Teams |
| 模型 | 對話、嵌入向量 | OpenAI 相容 | 路由、資料政策 | 原生介面、代管計費 |
| 登入 | 驗證、取得身分 | 內建帳號 | OIDC（Entra ID） | LDAP／AD、SAML |
| 簽章 | 簽署、驗證 | — | 系統層級簽核（不需轉接器） | 醫事人員憑證、自然人憑證 |

## 5. 應用模組與 Agent

| 模組 | 職責 | 主要需求 |
|---|---|---|
| intake 收件與任務 | 依證據規格產生任務、待繳清單、上傳、待歸類區 | TASK-* |
| classify 歸類 | 文件 → 證據規格／單位／期間 | CLS-01 |
| completeness 要素檢查 | 逐項判斷必備要素並附出處 | CMP-* |
| consistency 一致性稽核 | 比對辦法與紀錄：找出問題 → 解釋 → 分級 | CON-01 |
| mapping 對應與缺口 | 條款缺口；辦法與條款的對應 | MAP-* |
| doc_control 文件管制 | 編號、版次、生效流程、作廢、定期審查 | DCT-* |
| signoff 簽核 | 主管認可、核准，內容雜湊值 | SIGN-* |
| change_impact 變更影響 | 改版時的影響分析 | CHG-* |
| pdca 改善追蹤 | 改善行動，附新證據才結案 | PDCA-* |
| dashboard 燈號與佐證 | 燈號、準備度、佐證清單 | DASH-* |
| **Agent** bootstrap 導入分析 | 辦法 → 證據規格草稿 → 單位確認清單 → 缺口 → 報告 | BOOT-* |
| **Agent** monitor 稽核監控 | 定期巡檢、週報 | MON-* |

## 6. 主線資料流（MVP-0）

```
辦法(Word/PDF) ─► 解析切段 ─► [AI] 抽取應產生的紀錄 ─► 證據規格草稿 ─► 人審定稿
                                                                 │
                                                 依頻率產生各期任務 ◄┘
                                                                 │
紀錄上傳(任務/自由) ─► 解析切段 ─► [AI] 歸類 ─► [AI] 要素檢查 ─► [AI] 一致性稽核
                                                                 │
                                         人審（帶內容雜湊值）◄────┘
                                                                 │
                                  燈號／準備度 ─► 一鍵佐證清單 ◄──┘
```

## 7. 技術選型（暫定，於設計階段確認）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 資料庫 | PostgreSQL 16 + pgvector | 已定：單一資料庫同時處理關聯資料與向量 |
| 後端 | Python（FastAPI） | 文件解析與 AI 生態系最完整 |
| 前端 | MVP-0 用伺服器端渲染的簡單頁面 | 主線優先 |
| 副本存放 | S3 相容（地端可用 MinIO） | 支援寫入後鎖定，容易擴充 |
| 部署 | 容器（Docker Compose → 視規模改用其他方式） | 地端一鍵安裝 |

程式庫的資料夾結構見 [repository-structure.md](repository-structure.md)。
